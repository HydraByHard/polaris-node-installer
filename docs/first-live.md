# Первая реальная установка владельцем

Production во время разработки не меняется. Первый запуск проводится на **отдельной новой VPS**; действующий backup не используется для эксперимента.

0. Если GitHub release ещё отсутствует, сначала выполните однократную публикацию по docs/publish.md. Нельзя запускать команды с выдуманным download URL.
1. Проверьте Ubuntu22.04/24.04 amd64,1 ГБ RAM/4 ГБ свободно, root native-консоль, существующий SSH и возможность provider recovery. Выпишите IP новой VPS и новый свободный домен, например fi1.followyourpolaris.space.
2. В production Panel убедитесь, что версия3.4.11, и что фактический source-IP исходящих соединений Panel — ожидаемый208.123.185.211. При другой версии installer остановится; не обходите проверку.
3. Создайте отдельный API-токен на1день ровно с10 enrollment scopes из README. Скопируйте его только в скрытый prompt новой VPS; после установки удалите в Panel. Токен не равен паролю администратора и не одноразовый до отзыва.
4. Скачайте существующий versioned release, проверьте известный SHA из доверенного отчёта (или подпись с доверенным fingerprint), запустите. Ответьте на вопросы; создайте только новый DNS A/AAAA по подсказке. TCP80/443 публично,2222 только от source-IP Panel,8082 не публиковать. Не меняйте старые panel/sub/backup.
5. Дождитесь READY_FOR_TESTING, ONLINE Node и hidden+disabled Host. Проверьте, что новая нода отсутствует в текущей подписке, backup продолжает работать, прежние UUID inbound в Polaris personal не изменены.
6. С независимого источника проверьте HTTPS/h2 нового домена (по `/` ожидается404 с валидным TLS), недоступность2222 и8082. С Panel проверьте штатную ONLINE связь. TCP-connect без протокольного запроса сам по себе недостаточен.
7. Создайте изолированного тестового пользователя/Squad и отдельный тестовый Host только для нового inbound. Не включайте его для действующих пользователей. Получите индивидуальную тестовую подписку и проверьте **Hiddify** с внешнего устройства: импорт, TLS/SNI/h2/XHTTP, внешнийIP=новаяVPS, несколько сайтов и переподключение. Опционально `doctor --test-config /root/test.json` на ноде добавляет автоматический трафик-тест; JSON root0600, удалить после теста.
8. Проверьте OS reboot и Docker restart в согласованное тестовое окно: Node возвращается ONLINE, API остаётся закрытым, сертификат и nativekey не меняются. Убедитесь в наличии renew timer, snapshot/recovery и независимого SSH/nativeconsole.
9. После успешного data-plane теста удалите тестовые сущности, выдайте отдельный1дневный publish-token с8 scopes и выполните `polaris-node publish`, подтвердив точное PUBLISH. Прежние ссылки подписок остаются прежними. Убедитесь, что новая нода появилась только теперь. Отзовите токен.
10. При неудаче — `unpublish`, затем собственный `rollback --remove`. Сохраните private evidence локально; не загружайте state/ключи/токены в GitHub.

Готовность лаборатории не является утверждением об успешном production live-тесте. Он завершён только после пункта7 с реальным внешним клиентом и проверки сохранности старого VPN.
